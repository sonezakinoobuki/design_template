# 業務フロー図作成ガイド

本ガイドは、DOC-102 業務フロー図の各項目に何をどこまで書くかを説明する。共通のルールは設計書作成規約（STD-003）に従う。

## 1. この設計書の役割

**業務は、誰が、どの順で、どこでシステムを使って進めるか。**

| 項目 | 内容 |
|------|------|
| 目的 | システム化対象業務の流れと、人・システムの役割分担を定義する |
| 書かないこと | システム内部の処理手順（→ DOC-301） |
| 作成条件 | 業務プロセスを持つシステム |
| 要否 | 条件付き必須（規模Sは推奨） |
| ファイル単位 | 業務プロセス単位 |
| テンプレート | [業務フロー図_テンプレート](../02_テンプレート/要件定義/業務フロー図_テンプレート.md) |

## 2. 作成の流れ

| 項目 | 内容 |
|------|------|
| 作成する工程 | 要件定義 |
| 作成前に読むもの（入力情報） | DOC-101 要件定義書 |
| この設計書が正として定義するもの | 業務プロセス、アクター、業務とシステム機能の対応 |
| 関連設計書 | DOC-103 機能一覧 |

## 3. 項目別の記載ガイド

記載例は、共通の題材「個人向けタスク管理Webアプリ TaskNote」に基づく（03_記載例 参照）。要否・情報源の記号は設計書項目定義書（STD-004）2.2 に従う。

| No | 項目 | 記載内容 | 要否 | 情報源 | 記載例 |
|----|----|----|----|----|----|
| 4.1 | 業務プロセス一覧 | 業務ID（BIZ）、業務名、概要、頻度 | ◎ | 正 | BIZ-001｜タスク管理業務｜タスクを登録し、完了まで管理する｜毎日｜会員 |
| 4.2 | 業務フロー図 | アクター別のスイムレーン図（As-Is は任意、To-Be は必須） | ◎ | 正 | 会員：タスクを思いつく → TaskNote：タスク登録 → 会員：作業 → TaskNote：完了登録 |
| 4.3 | 業務とシステム機能の対応 | 各ステップで使う機能（FNC） | ◎ | 参照(DOC-103) | BIZ-001｜タスクを登録する｜FNC-003 |
| 4.4 | 例外業務 | 例外・差し戻し時の流れ | ○ 該当時 | 正 | 期限切れになった場合は、期限を再設定する |

## 4. 書き方のポイント

- スイムレーン（アクター別のレーン）で、人がやることとシステムがやることを分ける。
- To-Be（システム導入後）の流れは必須、As-Is（現状）は課題を説明するときだけ書く。
- システムを使うステップには機能ID を書き、機能一覧とつなげる。

## 5. よくある誤り

- システム内部の処理を細かく書く → 処理設計書に書く。
- 1枚の図に業務をすべて詰め込む（20ノードを超えたら分割する）。

## 6. レビュー観点

設計書作成規約（STD-003）14.2 の共通レビュー観点に加えて、次を確認する。

| No | 確認内容 |
|----|----------|
| 1 | すべてのシステム利用ステップに機能ID があるか。 |
| 2 | 例外時の流れが漏れていないか。 |

## 7. 小規模（規模S）での簡略化

業務が単純な個人開発では省略してよい。その場合は要件定義書の利用シーンで代える。
