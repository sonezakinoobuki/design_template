# モジュール構成設計書作成ガイド

本ガイドは、DOC-302 モジュール構成設計書の各項目に何をどこまで書くかを説明する。共通のルールは設計書作成規約（STD-003）に従う。

## 1. この設計書の役割

**ソフトウェアの内部は、どの単位に分かれ、どのように依存するか。**

| 項目 | 内容 |
|------|------|
| 目的 | ソフトウェア内部のモジュール・コンポーネントの分割と依存関係を定義する |
| 書かないこと | 物理的なサーバー構成（→ DOC-201）、各処理の手順（→ DOC-301） |
| 作成条件 | 複数のモジュール・コンポーネントで構成されるシステム |
| 要否 | 規模Mは推奨、Lは必須 |
| ファイル単位 | プロジェクトで1ファイル（大規模はサブシステム単位） |
| テンプレート | [モジュール構成設計書_テンプレート](../02_テンプレート/詳細設計/モジュール構成設計書_テンプレート.md) |

## 2. 作成の流れ

| 項目 | 内容 |
|------|------|
| 作成する工程 | 詳細設計 |
| 作成前に読むもの（入力情報） | DOC-201 システム構成設計書 |
| この設計書が正として定義するもの | レイヤー・モジュール構成、モジュールの責務、依存関係のルール、共通部品一覧 |
| 関連設計書 | DOC-201、DOC-301 |

## 3. 項目別の記載ガイド

記載例は、共通の題材「個人向けタスク管理Webアプリ TaskNote」に基づく（03_記載例 参照）。要否・情報源の記号は設計書項目定義書（STD-004）2.2 に従う。

| No | 項目 | 記載内容 | 要否 | 情報源 | 記載例 |
|----|----|----|----|----|----|
| 4.1 | アーキテクチャ方針 | 採用するアーキテクチャスタイル（レイヤード、クリーンアーキテクチャなど）と理由 | ◎ | 正 | レイヤードアーキテクチャ（表示・アプリケーション・ドメイン・インフラ） |
| 4.2 | モジュール一覧 | モジュールID（MOD）、名称、責務、配置（リポジトリ・ディレクトリ） | ◎ | 正 | MOD-01｜ドメイン｜業務ルール｜src/domain |
| 4.3 | 依存関係 | モジュール間の依存関係図と依存のルール（禁止する依存） | ◎ | 正 | ドメイン層は他の層に依存しない |
| 4.4 | ディレクトリ構成 | ソースコードのディレクトリ構成 | ◎ | 正 | src/ 配下のディレクトリ構成 |
| 4.5 | 共通部品 | 共通部品の一覧と用途 | ○ 該当時 | 正 | 日付ユーティリティ｜タイムゾーン変換｜MOD-04 |
| 4.6 | 共通方式の実装 | DOC-201 の共通方式（ログ、例外など）をどのモジュールで実現するか | ◎ | 正（方針は参照(DOC-201)） | ログ出力｜MOD-04｜— |

## 4. 書き方のポイント

- 依存のルール（どこからどこへの依存を禁止するか）を明文化する。構造が崩れるのを防ぐ最も重要な項目である。
- システム構成設計書の共通方式を、どのモジュールで実現するかを対応させる。

## 5. よくある誤り

- サーバー構成を書く → システム構成設計書に書く。
- クラスを網羅的に列挙する（ソースコードで分かることは書かない）。

## 6. レビュー観点

設計書作成規約（STD-003）14.2 の共通レビュー観点に加えて、次を確認する。

| No | 確認内容 |
|----|----------|
| 1 | 依存のルールに違反する設計がないか。 |
| 2 | 共通方式がすべて実現モジュールに対応しているか。 |

## 7. 小規模（規模S）での簡略化

規模Sでは作成しなくてよい。ディレクトリ構成だけ README に書く方法もある。
