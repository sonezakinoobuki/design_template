# 用語集作成ガイド

本ガイドは、DOC-003 用語集の各項目に何をどこまで書くかを説明する。共通のルールは設計書作成規約（STD-003）に従う。

## 1. この設計書の役割

**この言葉は、このプロジェクトで何を意味するか。**

| 項目 | 内容 |
|------|------|
| 目的 | 業務用語・システム用語・略語の意味を定義し、設計書間の解釈のずれを防ぐ |
| 書かないこと | データ項目の型・桁（→ DOC-204） |
| 作成条件 | 常に |
| 要否 | 規模Sは推奨、M・Lは必須 |
| ファイル単位 | プロジェクトで1ファイル |
| テンプレート | [用語集_テンプレート](../02_テンプレート/共通/用語集_テンプレート.md) |

## 2. 作成の流れ

| 項目 | 内容 |
|------|------|
| 作成する工程 | 共通 |
| 作成前に読むもの（入力情報） | プロジェクト概要書、要件定義書、業務フロー図 |
| この設計書が正として定義するもの | 用語、読み、定義、同義語・禁止表記、英語表記（命名に使用） |
| 関連設計書 | すべての設計書 |

## 3. 項目別の記載ガイド

記載例は、共通の題材「個人向けタスク管理Webアプリ TaskNote」に基づく（03_記載例 参照）。要否・情報源の記号は設計書項目定義書（STD-004）2.2 に従う。

| No | 項目 | 記載内容 | 要否 | 情報源 | 記載例 |
|----|----|----|----|----|----|
| 4.1 | 用語一覧 | 用語、読み、定義、分類（業務／システム／略語） | ◎ | 正 | タスク｜たすく｜業務｜会員が期限までに行う作業の単位 |
| 4.2 | 英語表記 | 命名（テーブル名・API名など）に使う英語名 | ◎ | 正 | タスク｜task｜— |
| 4.3 | 同義語・禁止表記 | 使ってはいけない言い換え | △ | 正 | 会員｜ユーザー、利用者（会員登録済みの人を指す場合） |
| 4.4 | 関連用語 | 混同しやすい用語との違い | △ | 正 | 会員｜利用者｜会員は登録済み、利用者は未登録を含む |

## 4. 書き方のポイント

- 設計中に新しい言葉が出てきたら、その場で追加する。
- 英語表記は、テーブル名・API のパス・変数名の命名の元になる。ここで決めておくと命名が揃う。
- 同じものを指す複数の言葉がある場合は、1つに決めて残りを禁止表記にする。

## 5. よくある誤り

- 一般的な IT 用語まで網羅しようとする（プロジェクト固有の意味を持つ語に絞る）。
- データの型・桁を書く → データ要件定義書の項目辞書に書く。

## 6. レビュー観点

設計書作成規約（STD-003）14.2 の共通レビュー観点に加えて、次を確認する。

| No | 確認内容 |
|----|----------|
| 1 | 設計書内で用語集にない用語・禁止表記が使われていないか。 |
| 2 | 英語表記が命名規則と整合しているか。 |

## 7. 小規模（規模S）での簡略化

規模Sでは任意だが、10語程度でも作ると命名のぶれを防げる。
