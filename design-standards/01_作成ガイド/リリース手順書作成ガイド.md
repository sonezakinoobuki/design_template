# リリース手順書作成ガイド

本ガイドは、DOC-502 リリース手順書の各項目に何をどこまで書くかを説明する。共通のルールは設計書作成規約（STD-003）に従う。

## 1. この設計書の役割

**どうすれば安全にリリースでき、失敗したらどう戻すか。**

| 項目 | 内容 |
|------|------|
| 目的 | 本番環境へのリリース・切り戻しの手順を定義する |
| 書かないこと | 恒常的な運用作業（→ DOC-501） |
| 作成条件 | 本番環境へリリースを行うシステム |
| 要否 | 条件付き必須（規模Sは推奨）。CI/CD で自動化されている場合は、自動化の内容と手動作業のみを記載する |
| ファイル単位 | 手順の種類ごと（初回リリース、定期リリースなど） |
| テンプレート | [リリース手順書_テンプレート](../02_テンプレート/運用/リリース手順書_テンプレート.md) |

## 2. 作成の流れ

| 項目 | 内容 |
|------|------|
| 作成する工程 | 運用 |
| 作成前に読むもの（入力情報） | DOC-201 システム構成設計書、DOC-501 運用設計書 |
| この設計書が正として定義するもの | 事前準備、リリース手順、確認手順、切り戻し手順 |
| 関連設計書 | DOC-201、DOC-501 |

## 3. 項目別の記載ガイド

記載例は、共通の題材「個人向けタスク管理Webアプリ TaskNote」に基づく（03_記載例 参照）。要否・情報源の記号は設計書項目定義書（STD-004）2.2 に従う。

| No | 項目 | 記載内容 | 要否 | 情報源 | 記載例 |
|----|----|----|----|----|----|
| 4.1 | リリース方式 | 手動／CI/CD、デプロイ方式（ブルーグリーン、ローリングなど） | ◎ | 正 | CI/CD｜main へのマージで自動デプロイ |
| 4.2 | 事前準備 | 事前確認事項、関係者への連絡 | ◎ | 正 | マイグレーションの有無を確認する |
| 4.3 | リリース手順 | 手順、実行者、所要時間 | ◎ | 正 | 1｜main にマージする｜本人｜5分｜CI が成功している |
| 4.4 | 確認手順 | リリース後の動作確認 | ◎ | 正 | 1｜ログイン画面が表示される｜HTTP 200 |
| 4.5 | 切り戻し手順 | 切り戻しの判断基準と手順 | ◎ | 正 | エラー率が上がったら切り戻す／1｜前のバージョンを再デプロイする |
| 4.6 | DB変更 | マイグレーションの実行方法と戻し方 | ○ DB変更あり | 正 | デプロイ時に自動実行｜戻し用のマイグレーションを実行 |

## 4. 書き方のポイント

- 切り戻しの判断基準と手順を、リリース前に必ず決める。
- CI/CD で自動化している部分は自動化の内容だけを書き、手動作業を詳しく書く。

## 5. よくある誤り

- 恒常的な運用作業を書く → 運用設計書に書く。

## 6. レビュー観点

設計書作成規約（STD-003）14.2 の共通レビュー観点に加えて、次を確認する。

| No | 確認内容 |
|----|----------|
| 1 | 切り戻し手順があるか。 |
| 2 | DB変更がある場合に戻し方があるか。 |

## 7. 小規模（規模S）での簡略化

規模Sでは、CI/CD の設定ファイルの場所と、切り戻し手順だけでよい。
