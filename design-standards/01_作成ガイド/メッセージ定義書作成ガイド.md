# メッセージ定義書作成ガイド

本ガイドは、DOC-208 メッセージ定義書の各項目に何をどこまで書くかを説明する。共通のルールは設計書作成規約（STD-003）に従う。

## 1. この設計書の役割

**利用者に、どの言葉で伝えるか。**

| 項目 | 内容 |
|------|------|
| 目的 | 利用者に表示するメッセージ・エラーコードを一元管理する |
| 書かないこと | メッセージを表示する条件（各画面・API設計書に記載） |
| 作成条件 | 利用者向けメッセージを持つシステム |
| 要否 | 規模Mは推奨、Lは条件付き必須。作成しない場合は各設計書に直接記載する |
| ファイル単位 | プロジェクトで1ファイル |
| テンプレート | [メッセージ定義書_テンプレート](../02_テンプレート/基本設計/メッセージ定義書_テンプレート.md) |

## 2. 作成の流れ

| 項目 | 内容 |
|------|------|
| 作成する工程 | 基本設計 |
| 作成前に読むもの（入力情報） | DOC-202、DOC-203 |
| この設計書が正として定義するもの | メッセージID、種別、文言、パラメータ |
| 関連設計書 | DOC-202、DOC-203、DOC-301 |

## 3. 項目別の記載ガイド

記載例は、共通の題材「個人向けタスク管理Webアプリ TaskNote」に基づく（03_記載例 参照）。要否・情報源の記号は設計書項目定義書（STD-004）2.2 に従う。

| No | 項目 | 記載内容 | 要否 | 情報源 | 記載例 |
|----|----|----|----|----|----|
| 4.1 | メッセージID体系 | 種別（情報・警告・エラー）と番号の付け方 | ◎ | 正 | エラー｜MSG-Exxx｜001〜999 |
| 4.2 | メッセージ一覧 | メッセージID（MSG）、種別、文言、埋め込みパラメータ、使用箇所 | ◎ | 正 | MSG-E002｜エラー｜メールアドレスまたはパスワードが正しくありません。｜—｜SCR-001 |
| 4.3 | 多言語 | 言語ごとの文言 | ○ 多言語対応 | 正 | MSG-E002｜メールアドレスまたはパスワードが正しくありません。｜Email or password is incorrect. |

## 4. 書き方のポイント

- 文言はここで一元管理し、画面・API 設計書はメッセージID だけを書く。
- 文言のトーンと型（直し方、起きたこと＋次にできること）は UXガイドライン（STD-007）11章に従う。
- パラメータ（{0} など）を使い、似た文言を増やさない。

## 5. よくある誤り

- 表示条件を書く → 画面・API 設計書に書く。

## 6. レビュー観点

設計書作成規約（STD-003）14.2 の共通レビュー観点に加えて、次を確認する。

| No | 確認内容 |
|----|----------|
| 1 | 使用箇所のないメッセージ・ID のないメッセージがないか。 |
| 2 | 表現が統一されているか（敬体、句点など）。 |

## 7. 小規模（規模S）での簡略化

規模Sでは作成せず、画面設計書に文言を直接書いてよい。
