# テスト計画書作成ガイド

本ガイドは、DOC-401 テスト計画書の各項目に何をどこまで書くかを説明する。共通のルールは設計書作成規約（STD-003）に従う。

## 1. この設計書の役割

**何を、どのレベルで、どこまでテストすれば完了とするか。**

| 項目 | 内容 |
|------|------|
| 目的 | テストの方針・レベル・範囲・環境・完了基準を定義する |
| 書かないこと | 個々のテストケース（→ DOC-402） |
| 作成条件 | 常に |
| 要否 | 必須（規模Sは DOC-402 に統合可） |
| ファイル単位 | プロジェクトで1ファイル |
| テンプレート | [テスト計画書_テンプレート](../02_テンプレート/テスト/テスト計画書_テンプレート.md) |

## 2. 作成の流れ

| 項目 | 内容 |
|------|------|
| 作成する工程 | テスト |
| 作成前に読むもの（入力情報） | DOC-101、DOC-104、DOC-201 |
| この設計書が正として定義するもの | テストレベル（単体・結合・総合・受入）と範囲、テスト観点、環境、完了基準 |
| 関連設計書 | DOC-402、DOC-403 |

## 3. 項目別の記載ガイド

記載例は、共通の題材「個人向けタスク管理Webアプリ TaskNote」に基づく（03_記載例 参照）。要否・情報源の記号は設計書項目定義書（STD-004）2.2 に従う。

| No | 項目 | 記載内容 | 要否 | 情報源 | 記載例 |
|----|----|----|----|----|----|
| 4.1 | テスト方針 | テストの目的、重点 | ◎ | 正 | 要件の受入条件をすべて自動テストで確認する |
| 4.2 | テストレベル | 単体・結合・総合・受入の範囲と担当 | ◎ | 正 | 単体｜関数・クラスの動作確認｜全モジュール｜開発者｜ENV-00 |
| 4.3 | テスト観点 | 機能、非機能（性能、セキュリティなど）、回帰の観点 | ◎ | 正 | セキュリティ｜他人のタスクを参照できないこと｜結合 |
| 4.4 | テスト環境・データ | 使用する環境（ENV）、テストデータの準備方法 | ◎ | 参照(DOC-201) | ENV-02｜結合・総合｜シードデータを投入する |
| 4.5 | 自動化方針 | 自動テストの範囲、ツール、CI での実行 | △ | 正 | 単体・結合｜テストフレームワーク｜プッシュごとに CI で実行 |
| 4.6 | 完了基準 | 完了とする条件（実施率、合格率、未解決不具合の扱い） | ◎ | 正 | 総合｜全テストケース合格、重大な不具合0件 |
| 4.7 | 不具合管理 | 不具合の記録・管理方法 | △ | 正 | 不具合は GitHub Issues で管理する |

## 4. 書き方のポイント

- テストレベルごとに範囲と完了基準を決める。完了基準がないとテストを終える判断ができない。
- 非機能要件（性能・セキュリティ）のテスト観点を忘れない。

## 5. よくある誤り

- 個々のテストケースを書く → テスト仕様書に書く。

## 6. レビュー観点

設計書作成規約（STD-003）14.2 の共通レビュー観点に加えて、次を確認する。

| No | 確認内容 |
|----|----------|
| 1 | すべてのテストレベルに完了基準があるか。 |
| 2 | 非機能要件のテスト観点があるか。 |

## 7. 小規模（規模S）での簡略化

規模Sではテスト仕様書の冒頭にテスト方針として数行で書いてよい。
