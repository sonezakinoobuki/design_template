# トレーサビリティマトリクス作成ガイド

本ガイドは、DOC-403 トレーサビリティマトリクスの各項目に何をどこまで書くかを説明する。共通のルールは設計書作成規約（STD-003）に従う。

## 1. この設計書の役割

**すべての要件は、設計され、テストされているか。**

| 項目 | 内容 |
|------|------|
| 目的 | 要件・機能・設計要素・テストケースの対応関係を一覧化し、漏れを検出する |
| 書かないこと | 各要素の内容 |
| 作成条件 | 常に |
| 要否 | 規模Mは推奨、Lは必須。各設計書の ID 参照から自動生成してもよい |
| ファイル単位 | プロジェクトで1ファイル |
| テンプレート | [トレーサビリティマトリクス_テンプレート](../02_テンプレート/テスト/トレーサビリティマトリクス_テンプレート.md) |

## 2. 作成の流れ

| 項目 | 内容 |
|------|------|
| 作成する工程 | テスト |
| 作成前に読むもの（入力情報） | DOC-101、DOC-103、各設計書、DOC-402 |
| この設計書が正として定義するもの | REQ → FNC → 設計要素（SCR/API/TBL/PRC等）→ TST の対応表、未対応の要素 |
| 関連設計書 | DOC-101、DOC-103、DOC-402 |

## 3. 項目別の記載ガイド

記載例は、共通の題材「個人向けタスク管理Webアプリ TaskNote」に基づく（03_記載例 参照）。要否・情報源の記号は設計書項目定義書（STD-004）2.2 に従う。

| No | 項目 | 記載内容 | 要否 | 情報源 | 記載例 |
|----|----|----|----|----|----|
| 4.1 | 要件→機能 | REQ と FNC の対応 | ◎ | 参照(DOC-103) | REQ-002｜FNC-002 |
| 4.2 | 機能→設計要素 | FNC と SCR／API／BAT／RPT／IF／PRC の対応 | ◎ | 参照(各設計書) | FNC-002｜SCR-001｜API-001｜—｜—｜—｜PRC-001 |
| 4.3 | 要件→テスト | REQ／NFR と TST の対応 | ◎ | 参照(DOC-402) | REQ-002｜TST-001、TST-002 |
| 4.4 | 未対応一覧 | 設計またはテストが存在しない要件・機能 | ◎ | 正 | 要件｜REQ-003｜テストケースなし｜次回リリースまで |

## 4. 書き方のポイント

- 各設計書に書いた上流ID を集めて作る。手で作るより、設計書の ID 参照から自動生成するほうが正確である。
- 最も重要なのは 4.4 未対応一覧である。空でない限りリリースしない。

## 5. よくある誤り

- ここで新しい対応関係を作る（対応関係の正は各設計書）。

## 6. レビュー観点

設計書作成規約（STD-003）14.2 の共通レビュー観点に加えて、次を確認する。

| No | 確認内容 |
|----|----------|
| 1 | 未対応一覧が空か、または対応予定が決まっているか。 |

## 7. 小規模（規模S）での簡略化

規模Sでは作成しなくてよい。要件定義書の要件ごとにテストケースID を書く方法で代える。
