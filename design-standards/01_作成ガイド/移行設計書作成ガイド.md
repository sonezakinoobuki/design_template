# 移行設計書作成ガイド

本ガイドは、DOC-503 移行設計書の各項目に何をどこまで書くかを説明する。共通のルールは設計書作成規約（STD-003）に従う。

## 1. この設計書の役割

**既存のデータ・システムから、何を、どう新システムへ移すか。**

| 項目 | 内容 |
|------|------|
| 目的 | 既存のデータ・システムから新システムへの移行の方式・変換仕様・手順・検証方法を定義する |
| 書かないこと | 移行の要求水準（→ DOC-104）、移行先のテーブル定義（→ DOC-204） |
| 作成条件 | 既存のデータ・システムからの移行があるシステム |
| 要否 | 条件付き必須 |
| ファイル単位 | プロジェクトで1ファイル（大規模は移行対象ごとに分割可） |
| テンプレート | [移行設計書_テンプレート](../02_テンプレート/運用/移行設計書_テンプレート.md) |

## 2. 作成の流れ

| 項目 | 内容 |
|------|------|
| 作成する工程 | 運用 |
| 作成前に読むもの（入力情報） | DOC-104 非機能要件定義書（移行性）、DOC-204 DB設計書 |
| この設計書が正として定義するもの | 移行方針、移行対象データ、データ変換仕様（マッピング・クレンジング）、移行手順、移行検証方法、切り戻し |
| 関連設計書 | DOC-104、DOC-204、DOC-502 |

## 3. 項目別の記載ガイド

記載例は、共通の題材「個人向けタスク管理Webアプリ TaskNote」に基づく（03_記載例 参照）。要否・情報源の記号は設計書項目定義書（STD-004）2.2 に従う。

| No | 項目 | 記載内容 | 要否 | 情報源 | 記載例 |
|----|----|----|----|----|----|
| 4.1 | 移行方針 | 移行対象（データ、機能、利用者）、方式（一括／段階）、移行要件 | ◎ | 正（要件は参照(DOC-104)） | 移行対象：旧アプリのタスクデータ／一括移行 |
| 4.2 | 移行対象データ | 移行元、移行先テーブル（TBL）、件数 | ◎ | 正 | 旧アプリのCSV｜TBL-002｜500件｜— |
| 4.3 | データ変換仕様 | 項目のマッピング、変換・クレンジングルール | ◎ | 正 | 期日｜due_date｜YYYY/MM/DD を YYYY-MM-DD に変換 |
| 4.4 | 移行手順 | 移行の手順（MIG ID）、実施時期、停止時間 | ◎ | 正 | MIG-001｜CSV を取り込む｜初回リリース前日｜なし |
| 4.5 | 移行検証 | 件数・内容の検証方法と合否基準 | ◎ | 正 | 件数｜移行元と移行先の件数を比較｜一致 |
| 4.6 | 切り戻し | 移行失敗時の戻し方 | ◎ | 正 | 1｜取り込んだデータを削除する |

## 4. 書き方のポイント

- 移行は一度きりの作業だが失敗の影響が大きい。必ずリハーサルを行う。
- 変換ルールは項目ごとに書き、変換できないデータの扱いも決める。

## 5. よくある誤り

- 移行先のテーブル定義を転記する → DB設計書を参照する。

## 6. レビュー観点

設計書作成規約（STD-003）14.2 の共通レビュー観点に加えて、次を確認する。

| No | 確認内容 |
|----|----------|
| 1 | すべての移行対象データに変換仕様があるか。 |
| 2 | 検証方法と合否基準があるか。 |
| 3 | 切り戻し手順があるか。 |

## 7. 小規模（規模S）での簡略化

移行がない場合は作成しない。設計書適用台帳に「移行なし」と記録する。
