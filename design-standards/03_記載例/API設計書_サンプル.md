# API設計書 API-001 ログイン

<!-- 実際のプロジェクトでのファイル名は API設計書_API-001.md とする -->

## 1. 目的

会員のメールアドレスとパスワードを検証し、以降の API で使うトークンを発行する API を定義する。

## 2. 対象範囲

| 区分 | 内容 |
|------|------|
| 対象 | ログイン API のインターフェース |
| 対象外 | トークンの検証方式（システム構成設計書のセキュリティ章） |

## 3. 前提・制約

- 共通仕様（データ形式 JSON、日時 ISO 8601 UTC、共通エラー形式）は API一覧に従う。

## 4. 仕様

### 4.1 API概要

| 項目 | 内容 |
|------|------|
| API ID | API-001 |
| API名 | ログイン |
| 目的 | 会員を認証し、トークンを発行する |
| 機能ID | FNC-002 |
| 呼び出し元 | [SCR-001 ログイン画面](画面設計書_サンプル.md) |

### 4.2 エンドポイント

| 項目 | 内容 |
|------|------|
| メソッド | POST |
| パス（または操作名） | /auth/login |

### 4.3 認可

| 項目 | 内容 |
|------|------|
| 実行可能なロール | 認証不要（全員） |
| データ単位のアクセス制御 | なし |

### 4.4 リクエスト

| No | 項目名 | 物理名 | 位置 | 型 | 必須 | ドメイン | API固有の制約 | 説明 |
|----|--------|--------|------|----|------|----------|---------------|------|
| 1 | メールアドレス | email | ボディ | string | 必須 | メールアドレス | — | ログインID |
| 2 | パスワード | password | ボディ | string | 必須 | — | 1文字以上 | ログイン時は形式チェックをしない（4.6 E002 に統一するため） |

### 4.5 レスポンス

| No | 項目名 | 物理名 | 型 | 説明 | データ出所 |
|----|--------|--------|----|------|------------|
| 1 | トークン | token | string | 以降の API の Authorization ヘッダーに付与する | 発行 |
| 2 | 有効期限 | expires_at | string（日時） | トークンの有効期限 | 発行時刻 + 24時間 |
| 3 | 会員ID | member_id | integer | ログインした会員の ID | TBL-001.id |

### 4.6 エラー

| エラーコード | HTTPステータス | 発生条件 | メッセージ |
|--------------|----------------|----------|------------|
| E001 | 400 | email が未入力、または形式不正。password が未入力 | 入力内容が正しくありません。 |
| E002 | 401 | email の会員が存在しない、またはパスワードが一致しない | メールアドレスまたはパスワードが正しくありません。 |
| E003 | 423 | 5回連続でパスワードを誤り、ロック中 | ログインに続けて失敗したため、30分間ログインできません。 |
| E999 | 500 | 想定外のエラー | 時間をおいて再度お試しください。 |

会員の存在有無を推測されないよう、会員が存在しない場合とパスワード不一致を同じ E002 で返す。

### 4.7 振る舞い

| 項目 | 内容 |
|------|------|
| 冪等性 | なし（呼び出すたびに新しいトークンを発行する） |
| 副作用（データ更新） | TBL-001 の最終ログイン日時・連続失敗回数を更新する |
| 同期・非同期 | 同期 |
| 性能目標 | NFR-002 に従う（95%が1秒以内） |

### 4.8 処理詳細

| 処理ID | 内容 |
|--------|------|
| PRC-001 | 認証処理（会員検索、パスワード照合、ロック判定、トークン発行） |

### 4.9 使用例

```http
POST /auth/login
Content-Type: application/json

{"email": "user@example.com", "password": "********"}

HTTP/1.1 200 OK
{"token": "eyJ...", "expires_at": "2027-01-02T00:00:00Z", "member_id": 1}
```
