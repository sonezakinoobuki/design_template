# プロジェクト概要書

## 1. 目的

TaskNote 開発プロジェクトの背景・目的・スコープを定義し、すべての設計書の前提を示す。

| 区分 | 内容 |
|------|------|
| 対象 | TaskNote の Web 版の初回リリース |
| 対象外 | 2回目以降のリリースの内容 |

## 3. 前提・制約

- なし（4.7・4.8 に記載）

## 4. 仕様

### 4.1 背景

タスクを紙のメモと頭の中で管理しており、期限を過ぎてから気づくことが月に数回ある。既存のタスク管理サービスは機能が多く、使い続けられなかった。

### 4.2 目的・ゴール

期限付きのタスクを一か所で管理し、期限切れのタスクを減らす。機能は最小限にとどめ、毎日使い続けられることを優先する。

### 4.3 成功基準

| 指標 | 目標値 | 測定方法 |
|------|--------|----------|
| 期限切れタスクの割合 | 10%以下 | 月末時点で、期限を過ぎた未完了タスク数 ÷ 当月の期限タスク数 |
| 利用継続 | リリース後3か月間、週5日以上利用 | ログイン履歴 |

### 4.4 スコープ

| 区分 | 対象 | 対象外 |
|------|------|--------|
| 業務 | 個人のタスクの登録・確認 | 複数人でのタスク共有 |
| システム | Web アプリ（PC・スマートフォンのブラウザ） | スマートフォン用ネイティブアプリ、期限通知 |
| 組織・利用者 | 会員登録した個人 | 法人・チーム |

### 4.5 ステークホルダー

| 関係者 | 役割 | 関心事 |
|--------|------|--------|
| 開発者 | 設計・実装・運用 | 少ない作業量で維持できること |
| 会員 | 利用者 | すぐにタスクを登録できること |

### 4.6 システム概要

```mermaid
flowchart LR
    U[会員<br/>ブラウザ] --> T[TaskNote]
    T --> DB[(データベース)]
```

### 4.7 前提条件

- 会員はモダンブラウザ（Chrome、Safari、Edge の最新版）を使う。
- クラウドの無料枠または低価格プランで運用する。

### 4.8 制約条件

| 種別 | 内容 |
|------|------|
| 予算 | クラウド費用は月額1,000円以内 |
| 期間 | 2027-03-01 までに初回リリース |
| 技術 | 開発者が保守できる技術に限る |
| 法令・規格 | 個人情報（メールアドレス）を扱うため、個人情報保護法に従う |

### 4.9 体制

個人開発のため省略する。
