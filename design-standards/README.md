## テンプレートの位置付け

テンプレート・作成ガイド・規約は、アプリを作るときに**参考にする汎用的なひな形**です。そのまま埋める書式ではなく、アプリに合わせて章・項目・形式を自由に変えて使います（[方針書 6.2](00_標準定義/01_設計書標準化方針書.md)）。

変えても残すことを推奨するのは、次の3点だけです。

- 要素に ID を付け、上流の ID を参照する。
- 同じ情報を複数の設計書に書かない。
- 決まっていないことは TBD と書く。

他のアプリでも役立ちそうな変更をしたときは、設計書適用台帳に1行残しておくと、後でこの標準に反映しやすくなります。

## 使い方（プロジェクトへの適用）

実際の開発の流れは [標準を使った開発フロー](00_標準定義/05_標準を使った開発フロー.md) を参照。設計書の選び方の要点は次のとおり。

1. 設計書体系定義書の「要否判断フロー」で、作成する設計書を決める。
2. 結果を「設計書適用台帳（DOC-002）」に記録する。
3. テンプレートをコピーし、作成ガイドを参考に、アプリに合わせて形を変えながら記載する。
4. 標準の不足・過剰に気づいたら改善要望として記録し、標準に反映する。

| 第4段階 | 実プロジェクトへの適用と改善 | 未着手 |
